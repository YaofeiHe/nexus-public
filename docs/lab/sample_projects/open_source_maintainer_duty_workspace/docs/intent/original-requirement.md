# 原始需求记录

## 用户原话

我要管理一个开源维护者值班工作区，包含 issue 分级、release blocker、回归测试证据、维护者交接、公共 README 发布检查和事故恢复记录。这个工作区要能区分 private 维护记录和 public 发布材料，不能把内部讨论、未确认漏洞细节、私有路径或 token 泄漏到公开版本。

它应该帮助维护者在值班期间判断哪些 issue 需要立即处理，哪些阻断 release，哪些需要回归验证，交班时下一位维护者应该读哪些记录。如果一次发布或修复失败，需要记录恢复步骤和下一次遇到类似问题时怎么先查恢复记录。

请生成人能读懂的项目说明、需求追踪、材料索引、维护 workflow、结构化 schema/index 和一个本地验证脚本。样例只能用于质量基准，不能让 Nexus 按项目名硬编码。

## 用户边界

- 不连接真实 GitHub API，不自动修改真实 issue、release 或 README。
- 不公开未确认漏洞细节。
- 不把 private maintainer notes 当作 public changelog。
- 不把单个 issue 例子当成值班系统的完整范围。

## 手工样例说明

这是人工创建的高质量样例项目，用于检验 Nexus 是否能把“开源维护者值班”理解成可执行工作区，而不是只保存原始输入。

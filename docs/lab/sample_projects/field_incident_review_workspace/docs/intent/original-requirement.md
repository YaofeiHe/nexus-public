# 原始需求记录

## 用户原话

根据 `reference_pack/strategy_notes.md`、`reference_pack/prior_chat_excerpt.md` 和 `reference_pack/existing_files_index.md` 构建一个现场事故复盘工作区。必须先记录读取和检索计划，说明每个文件要解决什么问题；再记录实际读取结果、提取出的需求、没有读到或仍不确定的内容；最后再生成项目结构。

工作区要能记录事故 intake、现场时间线、初步影响、根因分析、负责人分派、整改动作、验证证据和每周领导摘要。不要只写“检索完成”，也不要把用户举的某个事故例子当成范围上限。跳过的来源必须说明原因。

## 用户边界

- 不做真实事故责任判定，不替代法务、合规或安全部门结论。
- 不编造现场证据、人员姓名或设备编号。
- 公开摘要必须和内部调查记录分离。
- 未验证整改不能写成已完成。

## 手工样例说明

本样例模拟用户手把手要求 Codex 建出的高质量工作区。样例目标是呈现 Nexus 应学习的通用质量口径：先理解材料，再构建项目，而不是只保存原始输入。
